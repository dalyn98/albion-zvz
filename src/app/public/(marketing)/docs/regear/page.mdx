# 리기어 청구

ZvZ 에서 죽은 길드원이 잃은 장비를 보상받는 흐름입니다. 자동 생성과 수동 청구 두 가지 경로가 있고, 결제 수단은 **실버 / 제작** 듀얼 모드입니다.

## 사용 시나리오

- ZvZ 후 사망자의 장비를 실버로 보상하고 싶을 때
- 같은 장비를 길드 제작자가 만들어 박스로 픽업하게 하고 싶을 때
- 자동으로 잡힌 청구를 부위별로 가격 조정해서 승인할 때

## 사용법

### 자동 리기어 (블랙존 한정)

블랙존 ZvZ 에서 사망이 트래킹되면 시스템이 자동으로 청구를 만듭니다.

- 상태는 항상 `pending` — 청구자가 직접 검토하고 부위별 가격을 편집한 뒤 제출합니다.
- 자동 생성 자체는 cron 이 돌리고, 글로벌 토글이 OFF 면 cron 은 아예 돌지 않습니다.
- 청구 화면 (`/me/regear/[id]`) 에서 6개 슬롯 (weapon/head/armor/shoes/offhand/cape) 의 가격을 각각 조정 가능.

### 수동 청구

블랙존 외 사망이거나 자동 매칭이 누락된 경우 `/regear` 에서 수동으로 청구. 사망 스크린샷 + 자기 사망의 길드/시간/위치를 직접 입력합니다.

### 실버 / 제작 듀얼 모드

청구 수단을 두 가지 중 선택:

1. **실버** — 길드 금고에서 실버를 받음 (즉시 정산).
2. **제작** — 청구된 장비를 길드 제작자에게 큐로 전달, 제작 완료 후 박스로 픽업.

같은 청구 안에서 부위별로 다른 모드를 선택할 수도 있습니다 (예: 무기는 실버, 갑옷은 제작).

### 검증 흐름

청구가 들어오면 시스템이 `verifyDeathInWindow` 로 알비온 API 와 매칭합니다:

- 시간 윈도우 안에 해당 캐릭터의 사망 기록이 있는가
- `Victim.GuildName` 이 사이트의 홈 길드명과 일치하는가
- 매칭되면 자동 통과, 안 되면 "killboard 미검증" 표시 + 재확인 버튼

검증 실패 시 30분 정도 기다린 후 재시도하면 알비온 indexing 이 완료돼 통과되는 경우가 많습니다.

### 어드민 승인

청구가 제출되면 어드민 승인 큐에 들어갑니다. 어드민은 가격 적정성·이상 정황 (regear-anomaly 가 표시) 을 보고 승인/반려.

## 디자인 결정

### 왜 자동 리기어가 항상 pending 인가

자동 매칭이 청구를 알아서 승인까지 처리하면, 청구자가 자기 장비 구성/가격을 통제할 수 없어 "내 빌드는 더 비싼데?" "이 부위는 빠졌는데?" 같은 분쟁이 생깁니다. 청구자 본인이 한 번 손대고 제출 → 어드민 승인의 2단계가 신뢰성과 책임의 균형점입니다 (AGENTS.md hard rule #5).

### 왜 블랙존 한정인가

레드존/노란존/파란존 사망은 ZvZ 가 아닌 갱크·실수 케이스가 대부분입니다. 자동 청구의 false-positive 비용이 너무 커져서 블랙존만 자동화하고, 그 외는 멤버가 의식적으로 수동 청구해야 합니다.

### 왜 부위별 가격 편집을 허용하나

같은 T8 갑옷이라도 인챈트·어찬 장비 가격이 시장 변동에 따라 매번 다릅니다. 시스템이 추정한 가격을 그대로 쓰면 청구자가 손해를 보거나 길드가 과지급하는 케이스가 자주 발생 — 청구자가 자기 빌드의 시점 가격을 직접 입력하는 게 가장 정확합니다.

### 왜 듀얼 모드 (실버 + 제작) 인가

길드 금고가 빠듯하거나 길드에 활발한 제작자가 있으면 "실버 대신 만들어 줄게" 가 더 합리적입니다. 두 모드를 단일 청구 안에서 선택 가능하게 해서 부위별로 가장 효율적인 보상 방식을 골라쓸 수 있게 했습니다.

### 왜 길드명 매칭에 대소문자 무시인가

알비온 API 의 길드명 표기와 사이트 설정의 표기가 띄어쓰기/대소문자만 살짝 다른 경우가 흔합니다 (예: "Another Guild" vs "another guild"). lowercase 정규화로 매칭해야 false-negative 가 줄어듭니다 — 단, 다른 길드와 진짜 충돌은 길드명 자체가 달라 매칭 실패하므로 안전합니다.

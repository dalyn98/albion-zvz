# 킬보드 추적

알비온 공식 데이터에서 길드원의 킬·데스를 자동으로 가져와 사이트에 누적하는 시스템입니다. 청구·통계·업적의 기반 데이터입니다.

## 무엇을 할 수 있나

- ZvZ 이후 사망자 자동 청구 생성
- 멤버 상세 페이지에서 최근 활동 확인
- 길드 통계 (생존률, 무기 사용 패턴) 집계
- 업적 진행도 자동 갱신

## 어떻게 동작하나

### 자동 동기화

별도 조작 없이 시스템이 정기적으로 알비온 데이터를 가져옵니다. 사용자는 사이트에 들어와 결과만 확인하면 됩니다.

### 추적 범위

- **대상**: 알비온 홈 길드 멤버의 킬·데스 (잡은 사람 또는 죽은 사람이 길드원인 경우)
- **수집 정보**: 명성, 6개 장비 슬롯, 무기 종류, 사망 위치 (지역)
- **저장**: 사이트 자체 데이터베이스에 누적, 자동 리기어 매칭에 재사용

### 멤버 상세에서 확인

`/members/[디스코드ID]` 의 "최근 킬/데스" 섹션은 추적된 이벤트만 노출합니다. 외부 킬보드 사이트와 달리 청구 매칭, 업적 진행도 같은 길드 컨텍스트가 같이 보입니다.

### 전투 상세에서 확인

`/battles/[전투ID]` 에서는 ZvZ 한 판 단위로 묶인 화면을 봅니다. 참가자 카드 → 킬·데스 요약 → 클릭하면 펼쳐지는 상세 로그 구조라, 한 번에 너무 많은 데이터가 쏟아지지 않습니다.

## 규칙과 정책

### 사이트가 자체적으로 데이터를 보관합니다

알비온 공식 데이터는 30분 정도 반영 지연이 있고, 과거 데이터 검색에도 제약이 있습니다. 모든 화면이 매번 알비온 쪽을 호출하면 느리고 불안정해지므로, 사이트가 자체 저장소에 누적해서 안정성을 확보합니다.

### 알비온의 30분 반영 지연은 그대로 보입니다

청구 시 알비온 데이터로 사망 사실을 확인하는데, 너무 최근의 사망은 아직 알비온 쪽에 반영되지 않아 "킬보드 미검증" 으로 표시되는 경우가 많습니다. 시스템이 청구를 거절하는 대신 "재확인" 버튼을 노출해서, 30분 정도 후 다시 시도하면 통과하도록 만들었습니다. 이는 사이트 결함이 아니라 알비온 측 지연임을 자연스럽게 알리는 방식입니다.

### 무기 통계는 종류 단위로 묶습니다

같은 양손도끼라도 티어·인챈트·품질이 다르면 알비온 내부에서는 서로 다른 아이템으로 취급됩니다. 통계에서 그걸 다 따로 집계하면 "양손도끼 사용 빈도" 같은 의미 있는 숫자가 안 나오므로, **같은 종류의 무기는 한 줄로 묶어서** 표시합니다. 단, 킬 로그 자체는 정확한 장비명을 그대로 보여줍니다 — "어떤 인챈트로 죽었나" 를 정확히 보고 싶을 때 손실되면 안 되니까요.

### 6개 장비 슬롯만 추적합니다

대상 슬롯은 무기 / 머리 / 갑옷 / 신발 / 보조무기 / 망토 6개입니다. 가방·물약·음식·탈것은 일회성 소모재나 코스메틱 성격이라 청구·통계 의미가 약하므로 제외하고, 실제 손실이 큰 장비에 집중합니다.

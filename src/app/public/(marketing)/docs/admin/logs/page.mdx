# 로그 운영 / 루팅 검증

AGM 의 상점, 사이펀, 루팅 검증은 인게임 로그를 가져와 공식 장부로 쓰는 기능입니다. 문제는 알비온 로그가 항상 처음부터 완전하게 남아 있지 않다는 점입니다. 그래서 각 로그 기능은 `로그 운영 시작시간`을 기준으로 공식 집계 범위를 끊습니다.

## 로그 운영 시작시간

각 기능 화면의 `로그 운영 시작시간`에서 길드 상자, 사이펀, 루팅 검증의 시작 시각을 각각 정합니다. 같은 값은 `설정 → 길드`에서도 한 번에 볼 수 있습니다. 기준 시각 이전 행은 새 import, 멤버 잔액, 검증 결과에서 제외됩니다.

이 설정은 과거 데이터를 삭제하지 않습니다. 기존 데이터가 남아 있어도 공식 계산에서 제외하는 방식이라, 나중에 기준을 바꾸면 같은 원본 로그를 다른 범위로 다시 볼 수 있습니다.

운영 시작점을 정할 때는 다음 순서가 안전합니다.

1. 실제로 로그를 안정적으로 수집하기 시작한 시간을 정합니다.
2. 상점 관리 / 사이펀 관리 / 루팅 검증 화면에서 기능별 운영 시작시간을 저장합니다.
3. 그 이후의 로그만 import 하거나, 전체 로그를 붙여넣되 기준 전 스킵 수를 확인합니다.
4. import 후 멤버 화면과 관리자 장부가 같은 기준으로 보이는지 확인합니다.

## 사이펀 로그

사이펀은 `날짜 / 플레이어 / 목적 / 수량` 형식의 인게임 로그를 붙여넣습니다. 입금은 양수, 출금은 음수로 저장되고, 멤버는 `/me`와 `/me/siphon`에서 본인 캐릭터명 기준 잔량을 확인합니다.

가져오기 미리보기는 중복, 기준 전 스킵, 마지막 로그와의 공백을 보여줍니다. DB 마지막 기록 이후의 중간 구간이 비어 있으면 개인별 잔량이 왜곡될 수 있으므로, 경고가 뜨면 누락 구간을 먼저 확인합니다.

잘못된 로그를 저장했거나 불완전한 과거 로그가 섞였다면 `사이펀 관리`에서 원본 로그를 초기화합니다. 초기화는 현재 길드의 `siphon_ledger` 행만 삭제하고, 운영 시작시간은 유지합니다. 멤버 잔량은 남은 원본 로그 기준으로 다시 계산되므로 전체 삭제 후에는 0으로 보입니다.

## 루팅 로그 검증

루팅 검증은 전투 후 개인 루팅 CSV 와 길드 금고 입금 로그를 하나의 감사 단위로 묶어 비교합니다. 개인이 루팅한 수량보다 길드 상자 반납 수량이 적으면 미반납 의심 항목으로 표시합니다.

루팅 검증도 운영 시작시간 이전 행은 공식 결과에서 제외합니다. 기존 누적 로그가 완전하지 않은 길드는 루팅 검증 화면에서 먼저 시작점을 정한 뒤 새 전투부터 검증을 생성하는 것이 안전합니다.

결과에는 미반납 수량, 추정가, unresolved deposit row 가 분리되어 표시됩니다. 아이템명이 로그 언어 차이로 매칭되지 않으면 미해결 입금 행으로 남으므로, 검증 결과를 볼 때 미반납 목록과 미해결 입금 행을 함께 확인합니다.

## 권한과 감사

사이펀 장부를 import, 삭제, 초기화하려면 `SIPHON_MANAGE` 권한이 필요합니다. 루팅 검증은 어드민 대시보드에서 생성하고, 결과 처리 내역은 감사 로그로 추적합니다.

로그 기능은 길드 자산과 직접 연결됩니다. 운영 담당자를 최소화하고, 큰 정정 전에는 운영 시작시간과 감사 로그를 함께 확인하는 절차를 두는 것이 좋습니다.

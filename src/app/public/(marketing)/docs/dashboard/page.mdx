# 개인 대시보드

길드원이 자기 청구·보상·설정을 한 화면에서 관리하는 영역입니다. 어드민 화면과 분리돼 있어 본인 데이터에 집중합니다.

## 사용 시나리오

- ZvZ 후 자동 생성된 리기어 청구를 확인·편집·제출할 때
- 자기 보상 내역, 포인트 잔액, 청구 진행 상태를 한 번에 보고 싶을 때
- 알비온 캐릭터 인증 / 디스코드 닉네임 등 프로필을 갱신할 때

## 사용법

### 내 홈 (`/me`)

로그인 후 첫 진입 페이지. 다음 카드들이 한 화면에 모입니다:

- 최근 ZvZ 참여 / 사망 요약
- 내가 제출 / 승인 대기 중인 리기어 청구
- 포인트 잔액 + 최근 적립·차감 내역
- 업적 진행도 (멤버 상세의 축약 버전)

### 내 프로필 (`/me/profile`)

알비온 캐릭터 인증 / 닉네임 / 디스코드 표시명 등을 관리합니다. 알비온 길드를 떠난 경우 인증이 자동으로 풀리고 재인증을 안내합니다.

### 내 설정 (`/me/settings`)

길드 어드민이 정한 기본값을 본인 단위로 override 할 수 있는 항목 (예: 알림 시점, 기본 결제 모드) 을 관리합니다. 어드민 폼과 동일한 입력 패턴으로 만들어, "기본값 따르기" 같은 별도 옵션 없이 명시적으로 자기 값을 지정합니다.

### 내 리기어 청구 (`/me/regear/[id]`)

자동 또는 수동으로 만들어진 청구의 상세 화면입니다.

- 6개 슬롯의 가격을 부위별로 편집
- 부위별 결제 모드 (실버 / 제작) 선택
- 검증 상태 (killboard 매칭 통과 / 미검증) 확인 + 재확인 버튼
- 제출 후 어드민 승인 큐로 이동

### 내 요청 / 보상 내역 (`/me/requests`)

지금까지 제출한 청구의 상태 (pending / approved / rejected / paid) 와 보상 합계를 시간순으로 봅니다.

## 디자인 결정

### 왜 어드민 대시보드와 완전히 분리되어 있나

어드민이 보는 화면은 "전 길드원의 청구 큐, 가격 적정성, 정황 검증" 이고, 멤버가 보는 화면은 "내 청구 1건, 내 가격 1개, 내 보상" 입니다. 같은 데이터를 다른 관점으로 보는 화면을 한 페이지에 섞으면 양쪽 모두 복잡해져서, `/me/*` 와 `/admin/*` 를 처음부터 분리했습니다.

### 왜 자동 청구도 본인이 한 번 손대게 하는가

자동 매칭이 그대로 승인까지 가면 "내 빌드는 더 비싼데?" "이 부위는 왜 빠졌나?" 같은 분쟁이 생깁니다. 청구자가 자기 빌드를 한 번 검토 → 가격 / 결제 모드를 본인 의사로 확정 → 어드민 승인의 2단계 흐름이 책임과 신뢰성의 균형점입니다 (AGENTS.md hard rule #5).

### 왜 개인 설정이 어드민 폼과 같은 패턴인가

어드민 폼이 "셀렉트로 직접 값 지정" 인데 멤버 override 만 "기본값 따르기 / 직접 지정" 같이 섞어 두면 두 가지 경우 모두에서 사고가 납니다 — 어드민이 기본값을 바꿨을 때 멤버 화면이 의도와 다르게 변하거나, "기본값 따르기" 가 실제로 어떤 값인지 알 수 없게 됩니다. 같은 패턴 (셀렉트로 명시값) 으로 통일해서 어드민·멤버 둘 다 자기가 본 값이 곧 적용되는 값이 되게 했습니다.

### 왜 멤버 상세 (`/members/[discordId]`) 와 내 홈이 따로 있는가

`/me` 는 본인이 보는 운영 화면 (청구 / 보상 / 설정), `/members/[discordId]` 는 누구나 볼 수 있는 길드원 프로필 (활동 / 업적 / 무기 통계) 입니다. 같은 데이터의 일부가 겹치지만 관점이 달라서, 운영 액션이 가능한 본인 화면과 공개 프로필을 분리해 권한 / 노출 정책을 단순화했습니다.

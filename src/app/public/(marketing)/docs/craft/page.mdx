# 제작 리기어

리기어 청구 중 **제작 모드** 로 잡힌 장비를 길드 제작자가 만들어 박스로 전달하는 흐름입니다. 청구 큐 → 제작 진행 → 박스 픽업의 3 단계로 정리됩니다.

## 사용 시나리오

- 실버 대신 같은 장비를 길드에서 제작해 보상하고 싶을 때
- 길드 제작자가 자기 작업 큐를 정리해서 처리할 때
- 박스에 들어간 장비를 길드원이 픽업하고 사이트에 수거 확인할 때

## 사용법

### 제작 큐 (`/craft/queue`)

제작 모드로 청구된 장비를 한 화면에 모아서 보여줍니다.

- **장비 집계 카드**: 같은 itemId 끼리 합산해 "T8 무기 3, T7 갑옷 2" 처럼 표시 — 제작자가 한 번에 몇 개를 만들면 되는지 즉시 파악
- **도시별 그룹**: Caerleon / Lymhurst / Bridgewatch / ... 도시 헤더로 묶어, 도시별 분담 제작이나 이동 동선 계획 시 참고
- **납품 (deliver)**: 제작 완료된 장비를 박스에 넣고 박스 번호와 함께 사이트에 기록 → 청구자에게 자동 안내

### 내 제작 작업 (`/craft/my-tasks`)

`is_crafter` 권한을 받은 제작자가 자기 큐만 모아서 보는 화면입니다. 큐의 일부를 자기 이름으로 잡고 (claim) 진행 상태를 관리합니다.

### 제작 인벤토리 (`/craft/inventory`)

길드 제작자 / 어드민이 미리 만들어 둔 장비 재고를 관리합니다.

- 재고에 있는 장비는 청구가 들어올 때 그대로 박스에 넣고 끝 — 제작 사이클을 줄임
- 사전 재고 0 인 장비를 즉시 시장에서 사 박스에 넣은 케이스는 "경고 납품 (`inventory_warned`)" 로 마킹돼, 운영 지표로 관리

### 박스 픽업 (청구자)

박스 번호와 도시가 청구 화면에 노출됩니다. 청구자가 게임 안에서 해당 박스에서 장비를 꺼내고, 사이트에서 "수거 확인 (collected)" 버튼을 누르면 청구 종료.

## 디자인 결정

### 왜 정련 재료 트래킹은 폐기됐나

초기에는 "필요한 장비 → 필요한 재료 → 길드 창고와 비교" 흐름까지 자동화하려 했지만, 인게임 연동이 없어서 정확한 재료량을 알 수 없고 멤버에게 입력 부담만 늘어납니다. 길드의 실제 운영은 "재고가 있으면 쓰고 없으면 시장 구매" 가 자연스러워서, **장비 단위 (gear)** 만 트래킹하는 쪽으로 단순화했습니다.

### 왜 deliver 시점에 재고를 차감하나

박스에 장비가 들어가는 순간 길드 재고에서 빠져 청구자 손에 넘어간다고 보는 게 운영 모델과 맞습니다. 이전엔 "deliver=+1 / collect=−1" 였지만 collect 가 누락되면 재고가 부풀려져서 반전했습니다 — 박스 들어가면 즉시 −1 로 보수적 운영.

### 왜 경고 납품 (`inventory_warned`) 플래그가 필요한가

"길드 재고를 잘 운영하면 시장 구매가 거의 없어야 한다" 는 가설을 검증하려면, 시장에서 즉시 사서 박스에 넣은 케이스를 식별해야 합니다. 사전 재고 0 → 박스 직행이면 자동으로 마킹돼, "이번 달 시장 의존률" 같은 운영 지표를 뽑을 수 있습니다.

### 왜 도시별 그룹 헤더를 유지하나

알비온은 도시마다 제작 보너스 / 제작 가능 장비가 다르고, 박스도 도시 단위로 둡니다. 집계 카드를 도시별로 묶어두면 "Caerleon 박스에 어떤 장비를 채울지" 가 화면 한 번에 보이고, 제작 분담도 자연스럽게 도시 단위로 정리됩니다.

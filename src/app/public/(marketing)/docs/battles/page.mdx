# 전투 집계 & 이벤트 리포트

여러 명의 킬/데스를 시간·위치·참가자로 묶어 "ZvZ 한 판" 이라는 단위 (battle) 로 집계하고, 길드 단위의 결과 리포트로 정리하는 영역입니다.

## 사용 시나리오

- ZvZ 후 "이번 판은 몇 명이 어떻게 싸웠나" 를 한눈에 보고 싶을 때
- 사망자에 대한 자동 리기어 청구 매칭의 기준이 되는 battle 을 확인할 때
- 파티별 / 알라이언스별 결과를 분리해서 보고 싶을 때

## 사용법

### 전투 목록 (`/battles`)

알비온 공식 `/battles` API 에서 가져온 전투 데이터를 사이트 hard rule 에 맞춰 필터링한 결과를 리스트로 보여줍니다. 카드를 클릭하면 상세로 들어갑니다.

### 전투 상세 (`/battles/[id]`)

- 참가자 명단 (길드별, 알라이언스별 그룹)
- K/D 요약 + 명성·실버 합계
- 각 참가자 카드를 펼치면 그 사람의 킬/데스 로그
- "이 전투에서 자동 청구된 리기어" 링크

### 이벤트 리포트 (`/events/[id]/report`)

이벤트는 사이트가 정의한 운영 단위입니다 (정기 ZvZ, 연합전 등). 한 이벤트가 여러 battle 을 포함할 수 있고, 리포트는 그 합계를 보여줍니다.

### 파티별 보기 (`/events/[id]/party/[partyNumber]`)

이벤트 안에서 사람들을 파티로 묶어 분류한 화면 — 콜이나 빌드별 결과를 따로 보고 싶을 때 사용.

## 디자인 결정

### 왜 10명 미만은 자동 제외하나

길드원 1~2명이 갱크당한 작은 사건까지 전투 통계에 들어가면 평균값이 무너지고, 자동 리기어가 적합하지 않은 케이스를 청구로 끌어옵니다. 그래서 **10명 미만은 갱크로 분류해 집계에서 자동 제외** 합니다 (AGENTS.md hard rule #8). 이 규칙은 통계·업적 킬 집계에도 동일하게 적용됩니다.

### 왜 low-engagement-cut 가 있는가

10명을 넘어도 한 쪽이 거의 안 싸우고 끝난 전투 (예: 한쪽이 도주) 는 ZvZ 의미가 약합니다. `low-engagement-cut` 가 양쪽의 실제 교전 강도를 검사해 그런 전투를 추가로 잘라냅니다 — "10인 이상" 만으로는 부족한 부분을 메우는 2차 필터입니다.

### 왜 한 battle 의 다중 알라이언스를 분리하나

3-way 전투 (A vs B vs C) 가 흔한데, 알비온 API 는 이걸 하나의 battle 로 줍니다. 사이트는 이를 자기 길드 vs 상대 알라이언스 단위로 분리해서 표시·집계합니다 — 그래야 "우리 vs B 전투의 K/D" 같은 정확한 숫자가 나옵니다.

### 왜 limit 51 인가

알비온 `/battles` API 는 limit 파라미터에 51 이 상한입니다. 그 이상 요청하면 silent HTTP 400 (에러 메시지 없이 실패) 으로 떨어집니다. 사이트는 이걸 알고 페이지네이션을 51 단위로 잘라서 호출합니다 — 더 큰 윈도우가 필요하면 페이지를 여러 번 더 받는 식.

### 왜 이벤트가 battle 위에 따로 있나

ZvZ 1판 (battle) 은 알비온 데이터의 단위이지만, 운영자가 보는 단위는 보통 "이날 정모" 처럼 묶인 여러 battle 의 모음입니다. 이벤트를 1단계 위에 두면 청구·통계를 한 운영 세션 단위로 정리할 수 있습니다.

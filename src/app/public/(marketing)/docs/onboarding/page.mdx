# 봇 초대 & 첫 셋업

디스코드 봇을 길드 서버에 초대해서 사이트와 연동하는 self-serve 흐름입니다. 관리자가 별도로 SQL 을 만지거나 운영자에게 요청할 필요가 없도록 설계됐습니다.

## 사용 시나리오

- ZvZ 길드 운영자가 처음으로 사이트를 도입할 때
- 새 길드/얼라이언스가 봇을 초대해 자기 서브도메인을 만들 때
- 기존 길드가 봇을 다시 초대해야 할 때 (재설치)

## 사용법

### 1. 봇 초대

랜딩 페이지의 **"봇 설치"** 버튼을 누르거나, 짧은 단축 URL `/invite` 로 직접 들어갑니다.

```
https://albion-guildmanager.com/invite
```

디스코드 OAuth 화면에서 봇을 추가할 서버를 선택합니다. **서버 관리 권한** 이 있어야 봇 초대가 가능합니다 (디스코드 정책).

### 2. 디스코드 로그인

봇이 추가되면 사이트는 같은 디스코드 OAuth 로 봇을 초대한 사람의 신원을 확인합니다. 이 사람이 곧 첫 어드민이 됩니다.

### 3. 셋업 위저드

`/onboard/setup/[id]` 위저드가 자동으로 열립니다. 세 단계:

1. **기본 정보** — 사이트 슬러그 (예: `menhera` → `menhera.albion-guildmanager.com`), 표시 이름.
2. **알비온 홈 길드** — 트래킹할 알비온 길드를 검색·선택. East/West/Europe 3개 서버 중 하나.
3. **리워드 설정** — 자동 리기어 ON/OFF, 기본 보상 비율, 명성·실버 환율 등 (나중에 어드민에서 변경 가능).

### 4. 알비온 인증

길드원들이 사이트에 처음 접속하면 자기 알비온 캐릭터를 연결하라는 모달이 뜹니다. 캐릭터 이름 검색 → Albion API 가 본인 확인용 1회성 토큰을 검사 → 길드 멤버 자격 확인.

설정에서 **"미인증 길드원 접속 허용"** 을 끄면 미인증자는 자동으로 인증 화면으로 리디렉트됩니다.

## 디자인 결정

### 왜 self-serve 인가

운영자(우리)가 SQL 한 줄 만지지 않아도 새 길드가 봇을 추가하면 알아서 작동해야 한다 — 이게 multi-tenant SaaS 의 acceptance 조건입니다 (AGENTS.md 규칙 #10). 모든 신기능은 "Discord OAuth 로 봇만 새로 초대한 길드" 기준에서 기존 길드와 동등하게 작동해야 출시됩니다.

### 왜 Discord OAuth code 교환을 고집하나

Discord 의 OAuth state 파라미터는 길이 제한이 있어 모든 컨텍스트를 담을 수 없고, 일부 모바일 클라이언트가 query string 을 잘라먹기도 합니다. 그래서 봇 콜백 시 받은 `code` 를 한 번 더 교환해서 설치자의 신원을 직접 확인하는 방식을 씁니다 — state 만 믿으면 보안·UX 모두 깨집니다.

### 왜 슬러그 ≠ 디스코드 길드명인가

디스코드 길드명은 한글/이모지/공백을 허용해서 서브도메인 (`xxx.albion-guildmanager.com`) 으로 그대로 쓸 수 없습니다. 위저드에서 slug 를 별도로 받아 URL/내부 식별자로 사용하고, 표시용 이름은 slug 첫 하이픈 앞부분에서 자동 파생합니다 (예: `menhera-test` → "Menhera").

### 왜 모달 skip 규칙이 정교한가

알비온 인증 모달은 `getMemberAlbionIdentity` 가 멤버라고 인증한 사람에게만 뜹니다. 위저드 자체나 OAuth 콜백 진행 중인 페이지에 모달이 뜨면 위저드를 가려서 진행이 막혀버리기 때문에, `/onboard/*` `/onboarding/albion` `/api/auth/*` `/welcome-language` `/super-admin/*` 등은 명시적으로 모달을 스킵합니다.

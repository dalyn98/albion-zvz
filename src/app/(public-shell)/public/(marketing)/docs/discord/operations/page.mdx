# Discord 기능별 운영 상황

명령어 외에도 AGM은 Discord 버튼, 채널 공지, 개인 DM, 관리자 알림, 닉네임 동기화를 사용합니다. 짧고 안전한 작업은 Discord에서 끝내고, 편집 맥락이 긴 작업만 사이트로 이어집니다.

## Quick Starter Panel

### 이런 상황 때 사용하세요

- 신규 멤버가 사이트 링크와 인증 방법을 반복해서 묻습니다.
- Discord 채널에 항상 보이는 AGM 진입 버튼을 두고 싶습니다.
- 멤버가 이벤트 참가와 환전 신청을 Discord에서 바로 처리하게 만들고 싶습니다.
- 리기어 신청은 정확한 자격 검사를 거친 보호된 화면으로 연결하고 싶습니다.

### 운영 의도

운영자가 명령어와 URL을 반복 안내하는 일을 줄입니다. 공개 패널에는 개인 정보를 표시하지 않고, 버튼을 누른 뒤의 이벤트·환전 결과는 실행한 멤버에게만 보입니다.

### 이어지는 흐름

관리자가 `/agm admin quick-publish`로 Components V2 패널을 게시합니다.

- **이벤트 참가**: 다음 이벤트를 열고 역할군·빈 슬롯·현재 신청 상태를 Discord에서 확인합니다.
- **환전 신청**: 금액 입력 후 보류 안내를 확인하고 마지막 확정 버튼으로 신청합니다.
- **리기어 신청**: 현재 길드의 지원 상태와 본인 자격을 다시 검사한 뒤 정확한 신청 화면을 엽니다.
- **Discord 로그인 / 세션 갱신**: 웹 상세 편집이 필요할 때 사용할 1회성 로그인 버튼을 만듭니다.

## 이벤트 채널 공지

### 이런 상황 때 사용하세요

- 사이트에 이벤트를 만들었지만 멤버는 Discord에서 모집 공지를 봅니다.
- 특정 역할을 멘션해서 참여를 유도해야 합니다.
- 이벤트 상세와 신청은 사이트에서 관리하고 싶습니다.

### 운영 의도

이벤트 작성과 파티 편집은 사이트에서 정확히 하고, 모집 시작 신호는 Discord에서 보냅니다. 공지는 역할 멘션과 이벤트 링크를 포함해 멤버가 바로 신청 화면으로 들어가게 합니다.

### 주의

설정에서 이벤트 채널과 멘션 역할이 연결되어 있어야 합니다. 공지는 이벤트를 만들었다고 자동으로 항상 나가지 않고, 운영자가 발송 흐름을 확인해야 합니다.

## 이벤트 신청 버튼

### 이런 상황 때 사용하세요

- 멤버가 Discord에서 이벤트를 보고 바로 참가 의사를 내고 싶습니다.
- 다음 예정 이벤트를 Discord 명령 응답에서 바로 안내하고 싶습니다.
- 파티 편집은 사이트에서 하되, 신청 시작점은 Discord에 두고 싶습니다.

### 운영 의도

Discord에서 "참가하겠다"는 첫 행동을 쉽게 만들고, 실제 슬롯·파티·확정 관리는 사이트에 남겨둡니다. 전투 직전 모바일에서 이벤트 목록을 찾는 시간을 줄입니다.

## 개인 DM 알림

### 이런 상황 때 사용하세요

- 이벤트 집결 시간이 다가옵니다.
- 리기어, 환전, 포인트 환전 승인/거절 결과를 본인에게 알려야 합니다.
- 멤버가 사이트를 계속 새로고침하지 않아도 되게 만들고 싶습니다.

### 운영 의도

개인에게만 필요한 알림은 공개 채널이 아니라 DM으로 보냅니다. 채널 소음을 줄이고, 본인이 처리해야 하는 일만 직접 받게 합니다.

## 관리자 운영 알림

### 이런 상황 때 사용하세요

- 승인 대기, 상점 주문, 제작 납품, 미인증 멤버, 동기화 지연을 놓치기 쉽습니다.
- 운영자가 관리자 페이지를 계속 열어두지 않습니다.
- 운영진 전용 채널에서 처리할 일을 모아 보고 싶습니다.

### 운영 의도

관리자는 Discord에서 문제를 발견하고, 단순 승인/거절은 알림 버튼으로 바로 처리합니다. 리기어 알림은 실버 승인, 재고 출고, 제작 큐 전환을 구분하고, 다른 승인 알림은 승인/거절/상세보기 버튼으로 이어집니다.

상세 검토가 필요한 요청은 버튼으로 끝내지 말고 사이트의 승인/관리 페이지로 들어가세요. 가격 조정, 재고 확인, 권한 변경, 정책 판단은 Discord 메시지 안에서 처리하기보다 사이트 화면에서 맥락을 확인해야 합니다.

## Discord 닉네임 동기화

### 이런 상황 때 사용하세요

- Discord 닉네임과 Albion 닉네임이 달라 누가 누군지 헷갈립니다.
- 리기어, 출석, 킬보드, 포인트 기록을 같은 사람 기준으로 묶어야 합니다.
- 신규 멤버 인증 후 서버 닉네임을 정리하고 싶습니다.

### 운영 의도

인증된 Albion 닉네임을 길드 운영의 공통 이름으로 사용합니다. 운영자가 수동으로 Discord 닉네임을 정리하는 일을 줄이고, 통계·보상·킬로그 확인에서 같은 이름을 보게 합니다.

## Ephemeral 응답

### 이런 상황 때 중요합니다

- 멤버가 잔액, 출금, 인증 상태처럼 개인 정보를 확인합니다.
- 채널에 명령어 결과가 계속 쌓이는 것을 막고 싶습니다.

### 운영 의도

대부분의 `/agm` 응답은 명령을 실행한 본인에게만 보입니다. 공개 채널에는 필요한 고정 패널과 이벤트 공지만 남기고, 개인 안내는 개인 응답으로 처리합니다.

## 사이트와 Discord의 책임 분리

| Discord에서 하는 일 | 사이트에서 하는 일 |
| --- | --- |
| 빠른 진입, 이벤트 참가, 잔액 확인, 환전 요청 생성 | 이벤트 생성, 파티 편집, 상점/재고 관리 |
| 공개 공지, 개인 DM, 관리자 알림, 단순 승인/거절 버튼 | 감사 로그, 상세 내역, 권한 설정, 데이터 검증 |
| 신규 멤버 self-serve 안내 | 홈 길드, 보상 정책, 역할 매핑, 기능 토글 설정 |

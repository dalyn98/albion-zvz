# Discord 운영 판단 가이드

관리자는 Discord에서 운영 상황을 발견하고, 짧고 명확한 처리는 명령이나 버튼으로 끝내며, 편집 맥락이 긴 작업만 웹 대시보드로 이어갑니다.

## 신규 길드 설정

사용: `/agm setup`

봇을 막 초대한 길드는 설정 마법사를 만들거나 기존 설정을 이어갑니다. 새 설정 생성에는 Discord 서버 관리자 또는 서버 관리 권한이 필요하고, 진행 중 설정은 최초 설치자가 이어갑니다. 활성화가 끝난 길드에서는 관리자 대시보드로 안내합니다.

## 승인 대기 처리

사용: `/agm admin approvals kind`

리기어, 출금, 기부, 상점, 이벤트 지급, 제작 요청 중 실행자가 실제로 처리할 권한이 있는 항목만 보여 줍니다. 각 항목의 승인·거절 버튼은 기존 관리자 알림과 같은 서비스와 감사 경로를 사용합니다.

- 단순 승인·거절은 Discord에서 끝냅니다.
- 리기어 가격 수정, 재고 세부 확인, 정책 판단은 웹에서 처리합니다.
- `kind`를 고르면 특정 업무 큐만 빠르게 볼 수 있습니다.

## 이벤트 초안과 조기 운영 시작

사용: `/agm admin event-create title category`, `/agm admin event-start event`

`event-create`는 전투·FF·갱킹 종류별 생성 권한을 확인한 뒤 초안만 만듭니다. 시간, 장소, 파티와 모집 정책은 웹에서 검토해 발행하세요.

발행된 이벤트는 집결 시각에 자동으로 운영을 시작합니다. `event-start`는 예외적으로 집결 전 운영을 시작해야 할 때만 사용하며 실제 Albion 전투 시작 시각을 뜻하지 않습니다. 전체 이벤트 관리자 또는 해당 종류를 만들 권한이 있고 자신이 만든 이벤트인 경우에만 실행할 수 있습니다.

## 포인트 예외 보정

사용: `/agm admin points member delta memo`

보상 누락이나 오지급 정정처럼 이유가 남아야 하는 예외에만 사용합니다. 총액을 덮어쓰지 않고 append-only 장부와 관리자 감사 로그에 기록합니다.

- 지급은 양수, 회수는 음수입니다.
- `memo`는 필수이며 사람이 이해할 수 있는 운영 사유를 적습니다.
- 일반 이벤트 보상 지급 루틴을 대신하지 않습니다.

## 신규 멤버 안내 패널

사용: `/agm admin quick-publish message`

인증, 이벤트, 내 정보, 리기어, 상점, 지갑, 제작 버튼이 있는 길드원 패널을 현재 채널에 게시합니다. 같은 채널에 저장된 패널이 있으면 중복 게시하지 않고 갱신합니다.

멤버에게 일회성 명령을 반복 안내하기보다 신규 멤버 채널에 패널을 유지하고, 개별 작업은 `/agm me summary`나 구체적인 기능 명령으로 처리하게 하세요.

## 관리자 상세 화면

사용: `/agm admin dashboard`

승인 상세, 이벤트 편집, 상점 가격·재고, 권한·정책처럼 넓은 맥락이 필요한 작업은 대시보드에서 처리합니다. Discord 인터랙션을 기준으로 생성된 안전한 로그인 버튼을 사용합니다.

## 운영 경계

| 상황 | Discord | 웹 |
| --- | --- | --- |
| 승인 대기 발견·단순 처리 | `/agm admin approvals` | 가격·정책·상세 검토 |
| 이벤트 시작 | `event-create`, `event-start` | 일정·파티·슬롯 편집과 발행 |
| 포인트 예외 정정 | `/agm admin points` | 장부·감사 로그 확인 |
| 신규 멤버 안내 | `/agm admin quick-publish` | 실제 기능 화면 |
| 멤버 개인 상태 | `/agm me summary`, 기능별 조회 | 상세 내역과 편집 |

기존 `/agm admin killbot`은 제거되었습니다. Killbot 채널·토글·동기화 문제는 관리자 대시보드의 Killbot 설정과 `/battles` 기록을 함께 확인하세요.

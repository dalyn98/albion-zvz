# Discord 역할 권한

운영진을 사이트에서 다시 한 명씩 등록하지 않습니다. Discord 서버의 현재 역할에 사이트 capability를 연결하고, 역할을 가진 사람이 같은 권한을 함께 받습니다.

## 설정 방법

1. **어드민 → 권한**에서 Discord 역할을 선택합니다. 역할 ID를 직접 입력할 필요가 없습니다.
2. 역할 이름과 현재 영향 인원을 확인합니다.
3. 업무 프리셋을 고르거나 세부 capability를 조정합니다.
4. 저장 전에 추가·회수되는 권한 요약을 확인합니다.

주요 프리셋은 전체 길드 관리자, 리기어 운영진, 상점 보급관, 로그 운영 담당, 제작 책임자, 통계 분석가, 재정 운영진, 전술 운영진, 길드 설정 담당입니다. 프리셋을 적용한 뒤에도 필요한 capability만 추가하거나 뺄 수 있습니다.

`전체 길드 관리자`는 별도의 오래된 관리자 역할 목록이 아니라 `GUILD_ADMIN` capability 묶음입니다. 이벤트 종류별 생성자와 밤스쿼드 콜러도 같은 역할→capability 연결에서 관리합니다.

## 적용 시점

- 저장한 역할 연결은 즉시 권한의 기준이 됩니다.
- 권한을 변경한 운영자의 세션은 저장 직후 다시 계산됩니다.
- 권한·이벤트·재정·재고·복구 같은 중요 명령은 실행할 때 현재 Discord 가입 상태와 역할을 다시 확인합니다.
- Discord 역할을 잃었거나 서버에서 나간 사용자는 오래된 로그인 쿠키만으로 작업을 계속할 수 없습니다.
- 봇을 새로 초대한 길드도 온보딩에서 고른 관리자 역할이 같은 capability 연결로 생성됩니다.

기존 `admin_role_ids`, 이벤트 생성자 역할, 밤스쿼드 콜러 역할 값은 오래된 봇 경로와의 호환을 위한 출력값으로만 유지됩니다. 관리자는 이 값을 별도로 편집하지 않으며, 권한 판정은 capability 연결 하나만 사용합니다.

## 긴급 개인 예외

역할 변경을 기다릴 수 없는 사고 대응에만 개인 예외를 사용합니다.

- 현재 Discord 서버에 있는 실제 사용자만 선택할 수 있습니다. 봇과 로컬 길드 계정에는 운영 capability를 줄 수 없습니다.
- 사유는 필수이며, 만료는 15분 이상 30일 이하로 설정합니다.
- 만료된 예외는 자동으로 권한 해석에서 제외됩니다.
- 조기 회수할 때도 사유가 필요하고, 행을 삭제하지 않아 감사 기록을 보존합니다.
- 역할 기반 전체 관리자를 일시적으로 제한할 수 있지만 tenant 소유자의 bootstrap 접근은 개인 예외로 잠글 수 없습니다.

개인 예외는 평상시 권한 모델이 아닙니다. 반복해서 필요한 권한은 Discord 역할 연결로 옮기세요.

## 감사 기록

역할 연결과 개인 예외 변경에는 실행자, 대상 역할 또는 사용자, 변경 전·후 capability, 영향 인원, 사유와 만료가 기록됩니다. 두 운영자가 같은 설정을 동시에 편집하면 오래된 화면의 저장은 거부되므로 최신 상태를 다시 확인해야 합니다.

## 운영 원칙

길드 관리자와 제작자는 별개입니다. 길드 관리자는 정책과 승인을 다루고, 제작자는 제작 큐와 완제품 재고를 처리합니다. 필요한 업무만 capability로 위임하면 제작자에게 재정 승인까지 주거나 모든 관리자가 제작 업무를 맡는 상황을 피할 수 있습니다.

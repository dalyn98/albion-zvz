# ADR 0002: 길드별 리기어 지원 상태와 지급 방식 분리

- 상태: Accepted
- 결정일: 2026-07-30

## 배경

기존에는 `craft_regear_enabled` 하나가 실버 리기어와 제작 리기어의 지급 방식,
제작 화면 노출을 함께 표현했다. 이 구조에서는 리기어 제도를 전혀 운영하지 않는
길드와 실버로 지원하는 길드를 구분할 수 없고, 기능을 끈 뒤에도 기존 신청 기록을
어떻게 다뤄야 하는지가 불명확했다.

## 결정

길드의 리기어 설정을 다음 두 축으로 분리한다.

1. `regear_support_enabled`
   - 행 없음: `unconfigured`. 신규 온보딩에서만 사용하는 미선택 상태이며 실행
     경로에서는 미지원으로 간주한다.
   - `false`: `unsupported`. 신규 신청과 모든 리기어 변경을 차단한다.
   - `true`: `supported`. 리기어 운영 기능을 허용한다.
2. `craft_regear_enabled`
   - 지원 길드에서만 의미가 있다.
   - `false`: 실버 지급.
   - `true`: 제작 지급.

신규 온보딩은 지원/미지원 선택을 필수로 받고, 지원을 선택했을 때만 실버/제작
선택을 추가로 필수로 받는다. 미지원 선택은 기존 역할별 금액이나 제작 설정을
삭제하거나 덮어쓰지 않는다.

## 읽기와 쓰기 경계

- 미지원 상태에서도 기존 `regear_requests`, `regear_windows`, 리기어
  `craft_tasks`는 조회 가능하다.
- 웹 UI는 과거 이력을 읽기 전용으로 표시하고 신청·취소·수정·승인·반려·제작
  전달 버튼을 숨긴다.
- 서버 액션과 Discord 명령은 같은 상태를 다시 검사한다.
- 데이터베이스 트리거는 서비스 역할 RPC나 누락된 호출자 검사를 통한 우회를
  막는다. 테넌트 삭제 cascade만 예외로 허용한다.
- 자동 리기어와 스크린샷 정리는 미지원 길드를 건너뛴다.
- 미지원 상태에서 시작되는 이벤트는 disabled 리기어 정책을 동결한다. 이후
  지원을 다시 켜도 과거 이벤트가 소급해 신청 가능 상태가 되지 않는다.

`craft_tasks.task_kind = 'guild_order'`인 길드 발주는 리기어 도메인이 아니므로 이
경계에 묶지 않는다. 기존 발주 내비게이션 노출은 종전 `craft_regear_enabled`
값을 보존한다.

## 기존 길드 마이그레이션

- `pending`이 아닌 기존 테넌트에는 `regear_support_enabled = true`를
  `ON CONFLICT DO NOTHING`으로 추가한다.
- 기존 `craft_regear_enabled` 값은 그대로 유지하므로 Menhera를 포함한 운영
  길드의 실버/제작 동작은 변하지 않는다.
- `pending` 테넌트는 행을 만들지 않아 온보딩에서 명시적으로 선택하게 한다.
- 이미 명시된 지원 상태가 있다면 마이그레이션이 덮어쓰지 않는다.

## 적용 순서와 롤백

운영 적용 시에는 코드보다 마이그레이션 313~314를 먼저 적용해야 한다. 코드가
먼저 배포되면 아직 지원 행이 없는 기존 길드를 fail-closed로 판단할 수 있다.

문제 발생 시 애플리케이션을 이전 버전으로 되돌려도 새 설정 행은 무해하다.
데이터베이스 쓰기 경계를 되돌려야 한다면 314에서 추가한 트리거와 함수만 별도
후속 마이그레이션으로 제거한다. 기존 기록이나 지원 상태 행을 삭제하는 롤백은
하지 않는다.
